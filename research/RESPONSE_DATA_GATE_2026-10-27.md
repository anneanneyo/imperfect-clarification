# Есть ли готовые ответы и конечные исходы в UserVille и CLARITI?

27 октября 2026. Ограниченная проверка двух ближайших источников, после E008. Проверялось наличие **уже записанных** уточнений, ответов, связанной цели и результата исполнения. Возможность сгенерировать новые диалоги проверялась отдельно от наличия данных. Отсутствие файла в просмотренном релизе не означает, что его нет нигде.

## Результат

В проверенных файлах готового набора «вопрос → несовершенный ответ → конечный исход» нет. Обе работы дают полезные исходные задачи и код. Для нового сравнения на них потребовались бы генерация ответов, фиксированный исполнитель и повторяемая оценка. Поэтому они не закрывают немедленную потребность в наблюдаемых partial/IDK без нового модельного запуска.

| Проверенный источник | Что действительно доступно | Чего в проверенном файле нет |
|---|---|---|
| CLARITI, `data/data.xlsx`, закреплённый Git | 500 уникальных SWE instance IDs, исходные issues, patch/test_patch, переписанные запросы, вопросы трёх моделей | Колонок с ответами на уточнения, траекторий исполнения, результатов отдельных запусков |
| UserVille, публичный `test_ood.parquet` | 3584 конфигурации начального запроса и предпочтений | Готовых диалогов: везде только system+user; поле answer во всех строках — одинаковая заглушка; reward ground_truth null |

## CLARITI

Источник: [авторский репозиторий](https://github.com/sani903/Teaching-Effective-Clarification/tree/9d0f37e57dfde021e6589388f362d45b5901a356), commit `9d0f37e57dfde021e6589388f362d45b5901a356`. Корневая лицензия MIT относится к содержимому вне `enterprise/`; права исходных SWE-материалов отдельно не пересматривались, они не перепубликуются.

Таблица прочитана без изменения: `Sheet1!A1:AB501`, 28 колонок. Вопросы заполнены для 489 строк в `clarification_questions_grpo_3`, для 495 — в `clarification_questions_gpt5_nano_3` и для 495 — в `clarification_questions_gpt5_3`. Это количества **ячеек со списками вопросов**, не количества отдельных вопросов. Три колонки rewrites имеют 496/495/496 непустых значений. Причины пропусков не выяснялись; по ним нельзя пересчитывать опубликованный resolution rate.

В `openhands/training/train.py:560–690` есть генерация ответов из исходного issue и оценка answerability; незнание задаётся при недостатке информации в issue. Это исполняемый механизм получения новых ответов, а не доказательство наличия сохранённых диалогов в таблице. Файл `run_infer.py` и код обучения прочитаны как текст, не запущены. Статья использует отдельные модули уточнения и исполнения и reward по доступности/значимости информации; общая идея обучать answerability уже не наше отличие. [Первичный текст, §§3–6](https://arxiv.org/html/2604.14624v1).

Воспроизводимая схема и числа: [clariti_table_inventory.json](../results/response_data_gate/clariti_table_inventory.json). Читатель: [clariti_table_inventory.mjs](../experiments/clariti_table_inventory.mjs), принимает путь к исходному XLSX и выходному JSON; использует `@oai/artifact-tool` из bundled runtime. Копия источника осталась в `/private/tmp`, вывод содержит только схему и агрегаты.

## UserVille

Источник: [авторский репозиторий PPP-Agent](https://github.com/sunnweiwei/PPP-Agent/tree/abbb7b1594f90eb94cf9543878f88996b7cd21ac), Apache-2.0, commit `abbb7b1594f90eb94cf9543878f88996b7cd21ac`. README ведёт в [публичную папку данных](https://drive.google.com/drive/folders/1yJHQckiRTkshF8SScZHUK3sjp9SpqW2x). Найдены `train_12n1.parquet`, `test_id.parquet`, `test_ood.parquet`. Прочитан только последний, 23 848 775 байт; два других не загружались. Лицензия кода не считается автоматически отдельной лицензией всей папки Drive.

Проверены все 3584 строки OOD-файла: обе последовательности `prompt` и `extra_info.prompt` содержат ровно роли system,user, поле `answer` всегда равно `There is no answer`, а `reward_model.ground_truth` всегда null. Это входы для запуска среды, а не 3584 наблюдения поведения пользователей. Не использовались для обучения/оценки selector. Хеш файла фиксирует снимок изменяемой ссылки Drive; гарантии неизменности ссылки нет.

Код `envs/userville.py` действительно ограничивает ответы предоставленной информацией и допускает IDK. В gym-режиме скрытый контекст может включать полное issue, hints и сведения из gold patch, с отдельным отключением для amateur. Агенту возвращается строка ответа вместе с cost/reward tags. Для нашего эксперимента это требует явного решения, какая информация допустима в пользовательском ответе: нельзя считать служебные теги естественной человеческой репликой. Точная валидность симулятора этим чтением не установлена. [Статья, §4](https://arxiv.org/html/2511.02208v2).

Результаты: [userville_data_inventory.json](../results/response_data_gate/userville_data_inventory.json). Воспроизведение: `python experiments/userville_data_inventory.py --data <test_ood.parquet> --output <inventory.json>` с Python3.12 и PyArrow19.0.1. Для чтения установлен только PyArrow в отдельное временное окружение. Проекты авторов и модели не устанавливались, API-вызовов моделей нет.

## Что это меняет в плане

1. Не выдавать вопросы и задания из этих релизов за готовые response/outcome logs.
2. Не отвергать весь BAG по одной конфигурации: E008 проверил 76 ответов Qwen3-8B с одним prompt. Более широкая проверка опубликованных файлов может дать IDK и partial без новых затрат на генерацию. Заранее выбрать конфигурации, сохранять все пропуски и группировать по исходной задаче.
3. Если такого материала недостаточно, следующий модельный пилот должен сначала проверить механизм ответа и итоговый критерий на небольшой фиксированной выборке. Обучение большого оценивателя пока не обосновано.

Все URL, коммиты, размеры и SHA файлов: [source_manifest.json](../results/response_data_gate/source_manifest.json). Это проверка пригодности данных, не результат о превосходстве нашего метода.
