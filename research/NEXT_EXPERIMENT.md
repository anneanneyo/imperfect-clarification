# От точного примера к проверяемой гипотезе

Текущий статус 19 октября: выполнен [E002](E002_RESULTS.md) — обучаемый структурный оцениватель с формальной неоднозначностью ответов. Основная тема — уменьшение конечной ошибки с несовершенными уточнениями; адаптация ниже является дополнительной исторической веткой. Следующий уровень — содержательные ответы и независимый агентный исполнитель, а не увеличение числа erasure-прогонов.

## Диагностика E000

Запуск из корня проекта: `python3 experiments/clarification_sanity.py`.

Четыре равновероятные цели состоят из двух бинарных предпочтений. Ошибка в важном предпочтении стоит 0.9, в второстепенном — 0.1. Агент выбирает одну из четырёх комбинаций. Вопросы: весь профиль; только важное предпочтение; только второстепенное. Ответ либо раскрывает запрошенную часть, либо сообщает «не знаю».

Точный вопрос получает содержательный ответ с вероятностью p; важный частичный — 0.9; второстепенный — 1. Это намеренно сконструированный пример, не модель реального населения. Программа перебирает шесть значений p. Цена вопроса нулевая, задаётся не более одного вопроса.

Сравниваются: отсутствие вопросов, выбор в предположении идеального ответа, максимальный information gain с известным реальным каналом и точный Bayesian EVSI с тем же каналом. Все используют одинаковое оптимальное правило конечного решения и истинный канал после получения ответа. Таким образом, изолируется выбор вопроса, а не ошибка интерпретации ответа. Ни один метод не является воспроизведением SAGE или IG-clarifier.

При p=0.2 аналитически ожидаются потери 0.5 без вопроса; 0.4 при выборе полного профиля; 0.45 при выборе второстепенной детали; 0.095 при выборе важной детали. Проверки также включают отсутствие информации, общее оптимальное действие для всех целей, неравномерные priors, нормировку вероятностей и неотрицательность ценности информации до цены вопроса.

Это проверка формул и будущего evaluator. Четыре состояния и шесть настроек не являются независимым test set. Доверительные интервалы здесь не нужны: значения посчитаны точно. Никаких выводов о превосходстве факторизации, LLM или поведении людей пока нет.

## Пилот E001 — выполнена диагностическая часть E001a

Статус после рабочего запуска: [E001a](E001A_RESULTS.md) выполнен на внешних каталогах с синтетическими ответами и точным исполнителем. Это не LLM-пилот и не полная проверка H3. Ниже сохраняется исходная задумка; фактически выполненные условия и отклонения зафиксированы в [протоколе](E001A_PROTOCOL.md). Новые независимые синтетические каталоги не генерировались; использованы 89 внешних каталогов без повторного семплирования. Решение — не запускать сложное обучение на основании найденных эффектов.

После аудита 8 октября: соответствует кандидату A из `research/RESEARCH_CANDIDATES.md`. До расширения синтетики — проверка внешней среды по `research/STAGE1_REPORT.md`. Пилот начинается с адаптации к новой популяции по отдельным диалогам; персонализация одного человека после одного ответа не заявляется. В явном erasure-канале обязательный конкурент — адаптивная оценка частоты ответов по типам вопросов. Если она закрывает практически значимый зазор, сложная модель не оправдана. Ни перенос между пользователями, ни факторизация, ни оптимизация конечной пользы сами по себе новыми не считаются.

**Вопрос:** насколько ошибочная модель доступного ответа меняет выбранные вопросы и потери, и насколько эффект устраняется простой оценкой вероятностей по данным?

Сначала один домен с конечным каталогом и формальными ограничениями. Сгенерировать 200 независимых задач для разработки/пилота; сделать групповые train/calibration/evaluation splits, сохранив все версии каталога, ответы и перефразирования задачи вместе. Это development evaluation; финальный test создаётся и замораживается позже. Seeds, параметры генератора и принадлежность групп сохранять.

Изменять по отдельности важность неизвестного признака и вероятность/полноту ответа. Цели и каталоги держать одинаковыми в парных условиях. Включить как случаи смены оптимального решения, так и случаи с общим оптимальным решением. Начать с одного уточнения. Не ограничиваться независимым пропуском ответа: затем проверить зависимость ответимости от типа вопроса и наблюдаемого контекста.

Методы: no-ask; случайный вопрос; ideal-answer selector; IG; Bayesian EVSI с оценённым по train каналом; Bayesian EVSI с pooled train; истинный канал только как отдельно обозначенный oracle. Для отделения ошибок сначала использовать точное belief для всех методов, затем одинаковое оценённое belief. Предоставлять одинаковые наблюдаемые признаки и данные.

Основная величина — конечные потери при бюджете максимум одного вопроса; отдельно фактическая частота вопросов. Сравнения спрашивающих методов провести также при ровно одном вопросе. Стоимость вопроса и остановку анализировать отдельно, чтобы эффект не объяснялся разницей в числе вопросов. Для неопределённости — парные интервалы по независимым задачам, не по ответам одной задачи.

Адаптацию начать только после определения наблюдаемых labels. В игрушечном erasure-канале наличие ответа видно напрямую, поэтому его частоту можно оценить без скрытой цели. Это не означает, что произвольный смысловой канал идентифицируем без истинной цели. Режим с доступным z всегда помечать как привилегированный.

**Решение по результату:** если простой оценённый EVSI близок к oracle, искать конкретный нерешённый источник сложности до обучения нейросети. Если зазор есть, различить недостаток данных, ошибку belief, непредсказуемость ответа и недостатки модели канала. Только затем сравнивать факторизацию с прямой value head на одинаковых данных и вычислениях. Проверка H3 пока не началась.
