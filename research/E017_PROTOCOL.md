# E017: фиксированные языковые признаки для того же оценщика

27 октября 2026. Дополнительный baseline спроектирован во время обучения E016, **до получения любых его test generations и test scores**. E016 остаётся неизменным. Известен отрицательный малый пилот E015; часть train-generations E016 уже записана. Новая гипотеза здесь только диагностическая: мешают ли лексические признаки понимать смысл запроса. Не заявляем новый метод или проверку H3.

## Фиксированный дизайн

Те же96 train и48 test компонент E016, те же6 training targets, стоимость0.05, greedy executor и точные test branch outcomes. Никаких дополнительных profile/evidence/reveal/oracle labels. Признаки извлекать **только из нормализованного initial text**, идентичного входу E016 TF–IDF. Ни gold, ни ответы probes, ни правила банковского workflow в encoder input не добавлять.

Использовать ту же локальную закреплённую Qwen3-4B-Instruct-2507-4bit, без обучения весов. Токенизация самого текста, add_special_tokens=False, без chat template и без генерации ответа. Представление — final-normalized hidden state последнего токена последнего transformer layer,2560 координат, преобразовать в float32 и затем L2-нормировать в float64. Это обычный frozen-encoder baseline, не специально обученная retrieval embedding model. Не выбирать слой, pooling или prompt по оценке. Seed20261027, максимум512 входных токенов; превышение останавливает подготовку до исходов, не обрезает текст незаметно.

Тот же centered six-output ridge(alpha1), train-only centering/intercept, clipping[0,1], tie order no_ask/issue/product/money_gone/compensation/customer_name. Квалифицировать качество признаков только по результатам; термин «семантические» не означает, что они заведомо правильны. Не добавлять поиск alpha или другую pooling-схему после просмотра test.

## Порядок и бюджет

Заморозить protocol/code, E016 manifest и selector inputs, модель/версию, токенизированные input IDs и хеш исходника MLX qwen3. Убедиться, что нет test generations. После train E016 извлечь144 вектора одним последовательным процессом; модель не грузить одновременно с executor. До10 минут. Сохранить каждую завершённую запись отдельно; при ошибке не переходить к обычному fit и не подменять пропуск нулём. Частичный extraction не перезапускать молча.

Затем использовать только E016 train targets, сохранить predictions, model и fit manifest **до первого E016 test inference**. Независимо восстановить SVD-прогнозы. При провале до test явно зафиксировать незавершённый baseline; не задерживать E016 неопределённо. Полные E016 test outcomes переиспользуются для оценки всех методов, а не генерируются заново для нового метода. Дополнительная стоимость:144 forward passes без декодирования, время/память и input tokens; не выдавать их за нулевую стоимость.

## Метрики и решение

Accuracy/utility/ask rate и prediction MAE, выборы вопросов; paired utility differences embedding-minus-lexical, embedding-minus-train_constant, embedding-minus-fixed_issue. Component bootstrap10000(seed20261027), percentile95%; интервалы описательные, множественные сравнения и общий последовательный поиск сохраняются. Те же48 групп и те же ограничения, что в E016; они не становятся двумя независимыми тестовыми наборами. Не объявлять успех по одной более выгодной из нескольких метрик.

При улучшении получаем сильнее простой direct baseline, необходимый будущему сравнению H3. При отсутствии улучшения не заключать, что смысловой информации в запросе нет. Эта постановка не сравнивает direct/factorized, не моделирует новый механизм ответа и не даёт сама по себе публикационной новизны.
