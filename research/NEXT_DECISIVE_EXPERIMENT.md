# Следующий этап: исполнитель и границы диагностического сигнала

8 ноября 2026. [E026](REPORT_2026-11-08_E026.md), [формальная метрика](E026_METHOD.md), [E025](REPORT_2026-11-08_E025.md).

E026 завершён. Смена лучшего вопроса существует в двух из 12 знакомых задач при first_only и в одной при second_only; оба эпизода связаны общим шаблоном flight:2-26. Символический фильтр со случайным выбором имеет доступ к раскрытым правилам без ошибок понимания. Это не обученная политика и не эмпирическая модель ответов людей.

1. Зафиксировать отдельный протокол E027 до новых прогонов. Сохранить те же development-задачи и исходные E025/E026 артефакты. Имена Rental/Rentals использовать только через явно версионированную поправку. Не выбирать новые «красивые» задачи вместо сложных.
2. Проверить зависимость сигнала от исполнителя: равновероятный baseline; заранее заданная эвристика по видимым свойствам; при необходимости небольшой локальный языковой исполнитель. Исполнителю доступны только публичные меню, исходный запрос и фактически раскрытый текст ответа. Нельзя показывать остальные предпочтения, criteria.json, source-best/correct, разборы ошибок или все контрфактические исходы.
3. Отдельно считать исходную source-оценку, проверяемое удовлетворение предпочтений с U-границами и валидность выбранного ID. Не выдавать отсутствие проверки маршрута/цены за полноценную успешность поездки. Если слабый случайный baseline объясняет эффект E026, это должно быть основным результатом следующего этапа.
4. Сохранить одинаковый вопросный бюджет и четыре публичные темы вопросов. Full/first_only/second_only/no-information пока являются искусственными масками, а не частотной моделью пользователя. Реализуемый выбор вопроса нельзя оценивать по заранее известному полному профилю; такой выбор остаётся oracle.
5. До обучения оценщика явно задать доступное ему распределение скрытых целей и возможных ответов. Один профиль на задачу его не определяет. Проверить более сильные постоянные/простые методы, чтобы не повторять сценарий, решаемый контекстно-независимыми частотами.
6. Для самостоятельного результата нужен новый набор с контролем повторов шаблонов и независимая семантическая проверка. Текущие 12 задач — development; связный граф 96 train-задач не позволяет простое непересекающееся по шаблонам разбиение с сохранением всех строк. Нельзя трактовать два эпизода общего шаблона как две независимые репликации.

Не раскрывать E023 резерв; E021 остаётся незапущенным. Платные вызовы и переписка не нужны для ближайшего локального диагностического шага. E027 ещё не запущен; публикационная новизна не установлена.
