# E009: несовершенные ответы в шести конфигурациях BAG

27 октября 2026. [Протокол](E009_PROTOCOL.md) зафиксирован до чтения пяти новых конфигураций и их исходов. **Расширение корпуса оказалось полезным:** вместо 76 ответов одной модели доступны 2282 непустых ответа, связанные с 1392 исходными задачами. В них 181 лексический маркер незнания на 168 различных задачах. Это всё ещё симулированные ответы; маркер не равен смысловой разметке незнания.

В фиксированной выборке из 120 реплик один ассистентский просмотр нашёл 3 частичных, 3 неоднозначных, 6 случаев незнания/отказа, 2 неясных и 106 внешне полных ответов. Это предварительная разметка, **не человеческий gold standard** и не доказательство пользы нашего метода. Большая часть даже этой выборки отвечает на буквально заданный вопрос полностью.

## Корпус и целостность

Источник — [публичные данные BAG](https://huggingface.co/datasets/jsbaan/bag-paper-data/tree/58b2215ce80c74731d6d8dd3a843d2767943f569/dev), revision `58b2215ce80c74731d6d8dd3a843d2767943f569`, CC BY-SA3.0 по карточке с атрибуцией jsbaan/BAG и AmbigQA (Min et al., 2020). Взяты все шесть базовых user-файлов с одинаковым `50_belief` suffix, без выбора по результатам. Полные исходные файлы находятся вне проекта; их Git blob/LFS digests проверены, SHA256 сохранены.

Во всех файлах одинаковые 1832 уникальных source IDs. В OLMo2-7B одна дополнительная ненулевая запись `generations` не содержит строкового `response`: `1396774387387020988`; причина исключения сохранена. Непустых ответов с отсутствующим текстом исходного вопроса/уточнения нет. Ошибок JSON и дубликатов IDs нет. Для пяти новых конфигураций policy-логи не аудированы, поэтому доли непустых ответов не называются проверенной частотой ask.

Пользователя во всех шести конфигурациях играет `gemini-2.5-flash`: temperature0, n_samples1, max_new_tokens400; фактические generation configs совпали по этим полям. Точный API snapshot не установлен. Общие source IDs и один симулятор означают зависимые наблюдения. **2282 — число реплик, а не число независимых задач или людей.** Суммы по конфигурациям нельзя трактовать как случайную выборку из поведения пользователей.

## Разметка без новых исходов

Из каждой конфигурации выбраны 20 активных строк по SHA256 от фиксированного префикса, имени файла и source ID; пакет перемешан до просмотра. В нём только original query, clarification question и reply. Нет refs, reasoning, final predictions и judge labels. После чтения всех 120 реплик сохранены индивидуальные пояснения и хеш меток; только затем открыта привязка к моделям. Новые final/judge-файлы не загружались.

В выборке 116 уникальных исходных задач. 20 реплик Qwen3-8B уже читались в E008. Всего 27 записей относятся к 24 исходным задачам, уже просмотренным в E008, включая вопросы с иным уточнением. Полный overlap записан в `annotation_analysis.json`. Поэтому нельзя описывать просмотр как полностью наивную независимую разметку. Второго кодировщика/разметчиков-людей не было.

Убрали ранее просмотренные 20 реплик Qwen3-8B: остаются 86 полных, те же 3 partial, 3 ambiguous, 6 незнания/отказа и 2 unclear. Это sensitivity к повторному чтению реплик, **не удаление всех знакомых исходных задач**. Фиксированные 20 на модель не пропорциональны размерам конфигураций; суммарные 3/120 нельзя называть оценкой partial-rate во всех 2282 ответах.

На этих 120 репликах машинное правило нашло пять маркеров, все они совпали с предварительным классом явного незнания. Ещё один отказ пропущен правилом: пользователь говорит, что источника у него нет и поэтому он спрашивает ассистента (L025). Этот результат не валидирует precision/recall на всём корпусе.

## Что показывают конкретные partial-случаи

- **L105:** вопрос просит год версии сериала и имя персонажа. Ответ называет Lauren Tanner и сериал, но не год. Это непосредственно наблюдаемый пропуск одного из запрошенных аспектов. Нужен ли год для правильного конечного ответа — ещё не проверено.
- **L012:** пользователь подтверждает, что интересуется заставкой сериала, но не отвечает на дополнительный вопрос агента «какой ответ точнее». Здесь существенен дефект самого вопроса: часть фактической задачи переложена на пользователя.
- **L081:** пользователь выбирает серию книг, но не отвечает, кто именно спрашивает. И здесь пропущенная часть может быть вообще не нужна для решения исходной задачи.

Следовательно, обнаружение partial само по себе ещё не мотивирует новый алгоритм. Нужно установить, какая недостающая информация действительно меняет решение. Нельзя зачислять пользу в пользу нашей гипотезы только потому, что ответ формально неполон.

Есть и другой важный контроль: L095 буквально спрашивает у пользователя округ, который требовалось узнать из исходного запроса; симулятор называет округ. Это возможная передача самого ответа, а не уточнение намерения. Её истинность и доля в корпусе не проверялись. L086 вообще содержит утверждение вместо явного уточняющего вопроса, а симулятор отвечает IDK. Такие эпизоды нельзя без проверки смешивать с осмысленными вопросами о пользовательской цели.

## Исследовательское решение

**E008 исключил одну маленькую конфигурацию как достаточное основание; E009 показал, что отбрасывать весь BAG было бы преждевременно.** Расширенный корпус подходит для дальнейшего анализа механизма ошибок и подготовки данных, но ещё не для обучения и заявления выигрыша H3.

Следующая проверка должна разделить: (а) полезный вопрос с недостающей частью ответа, (б) вопрос о ненужной детали, (в) запрос самого фактического ответа у пользователя, (г) достаточный ответ с последующей ошибкой исполнения. Для сравнения ценности разных вопросов нужен один и тот же исполнитель. Смешивать финальные результаты разных assistant models в качестве такого сравнения нельзя. Сильный простой answerability/EVSI baseline остаётся обязательным. Новизна относительно CLEAT, CLARITI и Model-Free Preference Elicitation не установлена.

## Воспроизведение

`python3 experiments/bag_cross_model_screen.py --data <external-directory> --fetch` получает только шесть user-файлов из закреплённой ревизии; повтор без `--fetch` работает offline. Проверяются хеш протокола, исходников, неизменность blind pack и уже зафиксированных меток. Скрипт не генерирует метки ассистента автоматически: повторение агрегирования использует сохранённую предварительную разметку.
