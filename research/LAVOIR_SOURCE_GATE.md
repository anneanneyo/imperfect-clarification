# Lavoir: новый близкий источник и границы его использования

27 октября 2026. Источник найден при продолжении поиска после E012; проверка выполнена во время и после E013. Это исследовательский разбор одного train-раздела, а не воспроизведение опубликованной таблицы качества.

## Что это меняет для нашей работы

Lavoir уже предсказывает полезность уточнения по текстовому диалогу и кандидатам. Его цель обучения — изменение вероятности правильного класса у фиксированного снимка исполнителя после ответа. Данные включают неполные, неинформативные и избыточные ответы. Поэтому «нейросеть оценивает пользу вопроса с неполными ответами» нельзя заявлять как наш новый вклад. Исследовательскую ценность проекта ещё предстоит установить. [Описание и код авторов](https://github.com/moganai/lavoir), [карточка данных](https://huggingface.co/datasets/moganai/lavoir-dialogues).

Данные синтетические, сценарии и вероятности заданы авторами; ответы создавались языковой моделью. Карточка описывает проверку текстов другой моделью. Это внешний источник относительно нашего генератора, но не эмпирическое распределение человеческих ответов. Наличие peer review по просмотренным материалам не установлено. Код Apache-2.0, данные CC BY 4.0; веса модели не скачивались.

## Что проверено непосредственно

| Проверка | Результат |
|---|---:|
| Строки / исходные case-группы | 2546 / 486 |
| Только исходное обращение / после 1 вопроса / после 2 | 1374 / 893 / 279 |
| Возможные профили с ненулевой априорной массой | 44 |
| Несовпадения конечного класса с опубликованными правилами | 0 |
| Несовпадения posterior с пересчётом по schema и evidence | 0 |
| Доступные пары вопрос–ответ, `probes` | 11279 |
| Метки clean / partial / extra / unknown | 9811 / 543 / 422 / 503 |
| Пустые ответы | 0 |

Частоты — подсчёт опубликованных **меток**, не новая человеческая разметка семантики. Повторные состояния, уже известные признаки и недиагностический вопрос об имени входят в подсчёт. Поэтому эти доли нельзя отождествлять с безусловными вероятностями генератора из карточки.

Первый пересчёт последовательно строит prior по зависимым признакам. Второй независимо перебирает декартово произведение и использует рациональные дроби; проверены все 12730 значений posterior с допуском 2×10⁻⁹. Метки `gold` и поля `reveal` согласованы с профилями. Текстовое соответствие каждого ответа его `reveal` ещё не проверено нами. [Числа](../results/lavoir_source_gate/audit.json), [проверка](../results/lavoir_source_gate/verification.json).

## Две величины, которые нельзя смешивать

В [targets.py](https://github.com/moganai/lavoir/blob/af79b0a7a7f9864343223d3f7bd40a02747d0c1f/lavoir/targets.py) метка вычисляется как `p_after(gold) − p_before(gold)` по одному сохранённому ответу. Это изменение уверенности в правильном классе. Наша исходная цель — изменение ошибки **выбранного действия**; при argmax-решении это другая величина. Вероятность правильного класса может вырасти, хотя выбранный класс не изменится.

Если p — истинный posterior и G — неизвестный класс, то ожидаемое p(G) равно Σp(g)². Его улучшение соответствует уменьшению Gini impurity. При выборе одного наиболее вероятного класса точность равна max p(g). Это стандартное различие функций потерь, не новая теорема и не доказательство дефекта Lavoir. Сравнивать его probability-gain estimator с нашим decision-error estimator надо на одной конечной метрике и фиксированном исполнителе.

Отдельно в dataset есть `oracle_voi`. Его генератор не найден в просмотренном дереве кода, точная формула по каждому ответному событию не восстановлена. Поэтому независимое совпадение posterior **не означает**, что мы уже воспроизвели все значения oracle.

## Oracle может различаться при одинаковом видимом запросе

Группировка по точным `state + question + slots`, без ID/профиля/gold/probes, дала 1596 разных видимых входов. В 271 группе одному входу соответствуют разные векторы `oracle_voi`. В 122 группах нет ни одного вопроса, одновременно лучшего для всех записей группы, даже с учётом равных максимумов.

Пример — `train/banking_support/00001/p0/a`, `p1/a`, `p2/a`: одинаковый видимый вход, скрытые классы fraud/cards/loans. Для первого вектор предпочитает issue, для двух других — product. Видимый selector не может узнать вариант профиля из этих идентичных входов. Такое обучение на случайных скрытых исходах допустимо, но выучить можно условное среднее, а не точно воспроизвести каждую скрыто-зависимую метку.

Мы вычислили точный потолок согласия с лучшим вопросом в этих **2546 строках** для любого детерминированного selector, использующего только указанный видимый вход: 2397/2546 = **94.1477%**. Выбирается самый частый допустимый максимум отдельно для каждого одинакового входа. Независимый код подтвердил границу. Она относится к данной train-выборке и tie-aware соглашению, не к опубликованному тестовому результату авторов. Случайный selector не превысит эту границу в ожидании на той же равномерно взвешенной выборке.

435 значений `oracle_voi` ниже −10⁻⁸, минимум −0.321067. Отрицательная скрыто-условная или реализованная прибавка p(gold) сама по себе не ошибка. Её нельзя интерпретировать как отрицательный Bayes EVSI по всем возможным целям при возможности проигнорировать ответ. Все примеры сохранены: [коллизии](../results/lavoir_source_gate/visible_collisions.json), [отрицательные значения](../results/lavoir_source_gate/negative_values.json).

## Решение

Источник подходит для следующей ограниченной проверки: есть текстовые ответы, скрытые профили, проверяемый конечный класс, наблюдения для разных вопросов. Он пока не даёт готовой полной агентной оценки или человеческой валидации. `oracle_voi` не подаём selector как доступный признак и не используем как честный наблюдаемый baseline без явного обозначения привилегий. Разбиение строим по исходным case-группам, а не по строкам.

Следующий шаг — зафиксировать небольшой пакет начальных train-состояний, проверить семантику ответов и replay фиксированным локальным исполнителем. Одна опубликованная реплика на вопрос даёт один исход; она не заменяет распределение возможных ответов. До масштабирования нужно проверить, существует ли здесь пространство для лучшего выбора вопроса и насколько исходы объясняются самим текстовым исполнителем. Это продолжает исходную тему; на исследование дефектов чужого benchmark её не меняем.
