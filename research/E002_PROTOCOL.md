# E002: первый обучаемый оцениватель, 19 октября 2026

Основная цель возвращена к исходной: оценивать ожидаемое уменьшение ошибки решения при несовершенном ответе. Адаптация к смене пользователей не является обязательной частью этого эксперимента.

Этот протокол записан до первого запуска E002. Это контролируемая структурированная среда, не LLM и не независимая агентная валидация.

## Данные и доступ

Pinned flight_rec commit: 27466a7832d5aafff82017a659e08942e18b01ae. Один каталог — последний раунд каждой записи. train разделяется примерно 80/20 на fit/validation, seed=20261019, группировка по вектору предпочтений; одинаковые каталоги с переставленными вариантами также не могут пересекать splits. Из eval исключаются каталоги, встречавшиеся в fit/validation. Этот eval уже исследован раньше: называем его development holdout, не финальным нетронутым тестом.

Синтетическая популяция предпочтений строится только по fit-записям. Все методы знают один и тот же prior. Предпочтения eval-пользователей не используются. Обучающая метка — точное ожидаемое уменьшение regret фиксированного Bayesian-исполнителя после вопроса. Это привилегированная симуляционная разметка, не обратная связь из реальных диалогов.

## Несовершенный ответ

Восемь вопросов: price/stops/layover/arrival/american/delta/jetblue/southwest. Ответ сообщает знак коэффициента (-,0,+); либо пару возможных знаков, содержащую истинный; либо «не знаю». Пара выбирается равновероятно из двух подходящих пар. Это формальная неоднозначность/частичная информация, не понимание естественного языка. Ошибочных ответов, исключающих истинное значение, пока нет.

Пусть s — размах соответствующего признака среди трёх рейсов. Вероятность точного ответа: b[q] - .15*s, b=(.4,.7,.5,.75,.6,.6,.6,.6). Вероятность неоднозначного: .2 + .1*s. Остаток — «не знаю». Зависимость от контекста синтетическая, не эмпирическая. Функция одинакова на обучении и оценке: distribution shift не тестируем.

## Обучение и сравнения

- no-ask, random, ideal-answer selector;
- калиброванный простой baseline: для каждого вопроса коэффициент × ideal-answer gain, коэффициент обучается по тем же fit-меткам;
- direct ridge value estimator: отдельные коэффициенты для вопросов, признаки ideal gain, размах, их произведения, расстояние между двумя лучшими ожидаемыми наградами и масштаб различий признаков. Никаких тестовых ответов и истинных тестовых вероятностей на входе;
- oracle с истинным каналом, точным prior и исполнителем; отдельно oracle, который отбрасывает неоднозначные ответы, для измерения ценности их интерпретации.

Ridge использует стандартизацию только по fit; alpha из [0.01,0.1,1,10,100] выбирается по потере выбранного вопроса на validation. Предсказанную выгоду ограничиваем [0, ideal gain]. Это структурный direct baseline с аналитическим признаком ideal gain, не end-to-end нейросеть и не проверка H3.

Основной режим — ровно один вопрос, цена=0, чтобы изолировать выбор. Дополнительный — цена=.02 с возможностью no-ask; его результаты не используются при выборе alpha. Метрики: ожидаемая потеря, gap к oracle, MSE предсказания ценности, парный bootstrap по каталогам (условный на популяции). Никаких дополнительных подборов признаков после holdout-результата в этом запуске.

Проверки: нормировка каналов, независимый трёхсостоянийный пример, unknown-only и exact-only, неотрицательность истинной ценности и граница ideal gain, инвариантность перестановке рейсов, отсутствие пересечений splits. Сохраняем веса, scaler, разбиение, хеши, оценки кандидатов и сводку. Успех запуска означает работающий обучаемый baseline, но не новый научный вклад.
