# Два дополнительных источника для внешней проверки

27 октября 2026. Продолжение первоначального аудита, без установок и модельных вызовов.

## ReqClarifyBench

Статья [Chen et al., v1 от 9 октября](https://arxiv.org/abs/2610.13022) ведёт на [авторский архив Zenodo](https://zenodo.org/records/23031774). API Zenodo доступен, хотя web-reader не открыл страницу. Загружены 3 962 434 байта, MD5 сверен с API: `421b963803d9d9913d02468af9f0cf57`; SHA256 `c105f6dab1a6b79631169b0d94085532d41a7a1e09179314aa2fb5c291e670a3`. Проверены пути архива перед распаковкой. Ни один его скрипт не исполнялся.

Подтверждены 341 тройка `intent / requirements / atomic`: 140 gamecraft, 100 miniapp, 101 web. Имена задач внутри каждой тройки совпадают, atomic JSON корректны. Всего 1048 файлов; LICENSE и metadata указывают MIT. Есть prompts трёх personas, conversation runners и оценка требований. В `results/` лежат шесть агрегированных xlsx, не журналы отдельных ответов.

В проверенном архиве нет готового набора исполняемых приложений/тестов для повторения downstream outcome и нет опубликованных сырых диалогов. Requirement alignment и question-effectiveness скрипты обращаются к LLM judge. Поэтому архив полезен для следующего эксперимента с генерацией диалогов, но **сейчас не даёт бесплатной проверки конечного решения или эмпирической вероятности человеческого ответа**. Полного воспроизведения статьи нет.

Код учёта [reqclarify_inventory.py](../experiments/reqclarify_inventory.py), [manifest](../results/reqclarify_inventory.json). Исходный архив остался во временном каталоге; чужие данные в пакет проекта не добавлены.

## τ-bench: актуальная ветка и закреплённый релиз

На момент проверки [официальный README](https://github.com/sierra-research/tau2-bench/blob/main/README.md) уже описывает 2.0 и предупреждает о несопоставимости его входов с v1.0.1. Для небольшого компонента берём явно названный исторический **v1.0.1**, commit `fc0055dc4e0a316c3f83133267fbd6faaa770992`; это не утверждение «последняя версия». Новый voice/multilingual/intake не добавляем в нашу основную тему.

В pinned релизе retail содержит 114 задач (train74/test40), airline50 (30/20), telecom2285 в полном каталоге, но base114 (train74/test40). У retail112 задач basis DB+NL_ASSERTION и2 DB;40 содержат непустые NL assertions. Эти данные прочитаны из JSON, не перенесены с другой версии документации.

**Практическое решение:** проверить retail domain tools и состояния без LLM, затем восстановить полный reward contract. Только DB equality нельзя выдавать за официальный task success. Независимая проверка записана в [E007_PROTOCOL.md](E007_PROTOCOL.md); результаты будут в [E007_RESULTS.md](E007_RESULTS.md). Исходники, база и сценарии MIT, версия и SHA закреплены в harness. Установка полного voice/RL стека для этого не нужна.

Ни ReqClarifyBench, ни τ-bench не являются прямым восстановлением clarification-enhanced τ-bench из статьи IG-clarifier. Любые наши модификации ответов нужно определять отдельно и сравнивать с сильными исходными методами.
