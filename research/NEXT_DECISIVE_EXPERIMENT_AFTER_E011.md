# Следующий эксперимент после E011

27 октября 2026. Основная тема сохраняется: обучаемый выбор уточнения по уменьшению ошибки конечного решения при несовершенных ответах. [План после E009](NEXT_DECISIVE_EXPERIMENT_AFTER_E009.md) сохранён как история; его этап A выполнен в E010, начальная исполнимая установка — в E011.

## Что теперь установлено

E010 не дал надёжных causal question-value labels: ветви выбраны политиками, есть смена цели симулятором и спорные judge scores. E011 даёт проверяемое действие, но истинный механизм ответа задан и известен. На нём entropy и oracle EVSI совпадают; повтор этого расчёта с большим числом случайных seed не создаст нового результата.

**Следующий вопрос:** что можно надёжно выучить о полезности вопросов из небольшого числа ответов, если истинный механизм ответа неизвестен? Это исследовательский кандидат, не установленная новизна. Ближайшие сравнения — Model-Free PE, CLEAT, RegretBench; собственный E005 уже предупреждает, что сильная простая оценка частот может быть достаточной.

## Ближайшая работа без участия Ани

1. **Определить границу знания пользователя.** На development-сценариях retail отделить сведения, которые человек помнит; сведения, которые агент может сам прочитать; предпочтения пользователя; неопределённое предпочтение. Отказ сообщить, незнание и безразличие нельзя кодировать одним удалением ответа. Не расширять аудит всех benchmark без связи с этим вопросом.
2. **Составить небольшой проверяемый набор ветвей.** Для одной фиксированной цели — разные вопросы и правдивые полные/частичные/IDK ответы. Ответ не должен раскрывать недоступный пользователю факт, подменять цель или бесплатно разрешать её через финальное подтверждение. По возможности опираться на исходные task instructions; любые придуманные профили явно пометить как конструкцию. Без наблюдённого распределения не называть их частоты эмпирическими.
3. **Сверить точное отличие от ближайших методов.** Нужна таблица доступного feedback: известны ли goal во время обучения, вероятность назначения вопроса, response likelihood, конечный outcome; что известно только оценщику. Если совпадающий метод уже решает нашу постановку, воспроизвести его как baseline или изменить конкретный проверяемый вопрос, не придумывать новую архитектуру ради названия.
4. **Только затем заморозить протокол ограниченных наблюдений.** Все learners получают один журнал с одним случайно назначенным вопросом на эпизод, одной репликой и одним исходом; назначения известны. Установить бюджеты и разбиение по исходным семьям до оценки. Не передавать oracle K, скрытый тестовый режим или ID цели selector. Истинная цель может быть training supervision только одинаково для всех сравниваемых методов и с явным раскрытием.
5. **Сравнить с сильными простыми оценками.** Минимум: частоты типов ответа с регуляризацией + Bayes/EVSI; прямой предиктор конечной полезности с не менее информативными признаками; раздельная модель ответа/исхода; no-ask и oracle как разные ориентиры. Одинаковые наблюдения, tuning budget и вычислительные расходы. Не считать выигрыш над always-ID доказательством преимущества факторизации.

## Что остаётся открытым в экспериментальном контракте

- E011 проверяет только выбор и изменение DB. Полное действие агента требует подтверждения пользователя, правильного ответа и соблюдения правил среды. Это надо реализовать отдельно; утверждение полного agent success сейчас недопустимо.
- Для задаваемого механизма K точное суммирование полезно как oracle. Для естественных ответов нужны повторения, валидация сохранения цели и надёжная оценка результата. Один ответ не определяет ожидаемую ценность вопроса.
- Исходные 100 семей E011 уже просмотрены как инженерный материал. Метка reserved не делает их новым закрытым финальным тестом. Финальный тест потребуется сформировать отдельно и не использовать при выборе гипотезы.
- Новые модельные запуски требуют конкретной модели и воспроизводимого доступа. Сейчас полезная работа — постановка, проверяемые ветви и сравнение информационных условий; сам факт отсутствия API не является препятствием для этих шагов.

## Условия остановки конкретной исследовательской ставки

Не масштабировать H3, если простой метод не уступает после честной настройки; если наблюдаемый эффект объясняется неверной целью/оценкой; или если выигрыш появляется только после специально придуманного под него канала. Отрицательный результат должен менять решение, а не запускать ещё один похожий опыт с удобными параметрами.

Для статьи остаются обязательными подтверждённый вклад, надёжные данные и независимая проверка. Сейчас готова часть экспериментальной инфраструктуры и несколько отрицательных результатов. Цель публикации активна; ни журнал, ни научрук автоматически не получают материалы.
