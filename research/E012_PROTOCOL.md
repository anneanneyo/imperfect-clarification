# E012: достаточно ли пяти частот вместо сложного оценивателя?

27 октября 2026. Исследовательский development-пилот после E011. До этой записи известны все E011 oracle outcomes и средняя точность always-contents92.8893%. Выбор постановки поэтому exploratory, не подтверждающий тест. Первые12 исходных train instructions retail уже отобраны по SHA и прочитаны; отдельный качественный разбор не является экспериментальной разметкой поведения людей.

## Структурная проверка

В E011 тип ответа k наблюдаем по отдельному тегу. K(y|g,q,x)=alpha(q,k) R(y|g,q,x,k), где alpha не зависит от скрытой цели и семьи, а R полностью задан. При наблюдаемом k множитель alpha сокращается в Bayes. Исполнитель не зависит от неизвестных alpha. Ожидаемая точность вопроса поэтому линейна по alpha: sum_k alpha(q,k) A(x,q,k). Для order_id/total/count по одному свободному параметру answer/IDK; для contents два свободных параметра full/partial/IDK. Всего пять.

Доказать формулу и проверить её по прямому перечислению на всех100 семьях. Это известная вероятностная декомпозиция, не новая теорема. Не переносить её на случай ненаблюдаемого типа, зависящих от цели частот или неизвестного выбора содержания частичной реплики.

## Обучаемый сильный простой baseline

Единственная цель численного опыта — установить, насколько сильна оценка этих пяти параметров по малому числу реплик. Не сравнивать архитектуры и не заявлять H3.

- Сохранить60 development/20validation/20reserved families из E011. Для оценки использовать прежние20reserved, явно назвав development evaluation: они уже анализировались, закрытого теста нет. Validation в этом опыте не использовать, настройки не подбирать.
- Только прежний imperfect канал, без изменения его частот/формы. Цена вопроса0.05. При равенстве выбирать no-ask, между вопросами прежний фиксированный порядок.
- 30 seed:20261100…20261129. В каждом seed один вложенный журнал1024 взаимодействий. Бюджеты0/16/64/256/1024. Семья выбирается равномерно из60, цель равномерно внутри, вопрос равномерно из4. Response действительно сэмплируется из прежнего K, включая текстовые значения/tags. Скрытая цель не записывается в learner log.
- Обучаемая информация — номер вопроса и наблюдаемый тип ответа. Нет counterfactual outcomes, истинных alpha, скрытого профиля или test goal. Структура R и prior остаются привилегированно известными всем model-based baselines. Никаких конечных reward labels baseline не требует в этом частном случае.
- Оценка вероятностей: независимый Dirichlet(1,…,1) по наблюдаемым категориям каждого вопроса. Это три Beta(1,1) и один Dirichlet(1,1,1), без tuning. Бюджет0 — тот же prior.
- `learned_contextual`: подставить частоты в аналитическую ценность для каждой семьи и выбрать q/noask.
- `learned_fixed`: выбрать один вопрос/noask по среднему предсказанному return на60 development семьях; применять его ко всем evaluation семьям.
- Контроли: no-ask, фиксированный contents, oracle с истинными alpha. Always-contents выбран как сильный контроль после E011, а не найден на новом закрытом test. Не подавать это преимущество информации одному обучаемому методу.

Метрики: точная ожидаемая accuracy/utility и gap к oracle на20 evaluation семьях, MAE предсказанной accuracy по четырём вопросам, число выбранных q/noask. Усреднять семьи поровну. По30 seed показать mean и sample SD, не выдавать их за неопределённость переноса на новые задачи/людей. Сохранить per-seed данные, fitted probabilities и исходные наблюдения.

## Проверки и критерий решения

Проверить непересечение семей, длину/вложенность журналов, одинаковые журналы двух learners, отсутствие latent goal в полях learner, нормировку вероятностей, posterior cancellation и точное совпадение линейной декомпозиции с E011. Независимо пересчитать хотя бы fitted counts по сохранённым журналам. Равенство oracle и entropy из E011 не является результатом данного обучения.

Если simple baseline остаётся близок к oracle, не расширять обучение на этой конструкции до нейросети. Даже заметный gap при маленьком бюджете не доказывает преимущество раздельной архитектуры: неизвестных параметров всего пять. Не менять канал после результата ради headroom. Следующий шаг должен касаться неизвестной семантики/выбора содержимого ответа и реальных ограничений знания пользователя, если это обосновано исходными сценариями и литературой.

Новых моделей/API/внешних действий нет. Успех публикации и независимая агентная проверка этим опытом не достигаются.
