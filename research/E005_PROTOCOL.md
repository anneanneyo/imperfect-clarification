# E005: одинаковые наблюдения, прямой и раздельный оцениватели

27 октября 2026. Протокол записан до вычисления E005. Это ограниченная CPU-проверка механизма H3 из PLAN.md, **не проверка всей H3 с текстовым encoder, learned belief и LLM-executor**. E002/E004 и прежний development holdout уже анализировались: независимой подтверждающей выборки здесь нет.

## Вопрос и ограничения

Можно ли по отдельным наблюдаемым ответам и исходам обучить оценку пользы вопроса; даёт ли явное оценивание канала преимущество перед прямой регрессией при одинаковом журнале взаимодействий? Само преимущество более чистой метки не является преимуществом архитектуры, поэтому обязательный сильный контроль — прямая регрессия с аналитическим снижением шума.

Сохраняем конечный prior и точную модель полезности из E002. Это сильное привилегированное знание о среде, **не разметка скрытого состояния текущего пользователя**. В симуляторе форма ответа независима от предпочтения при заданных каталоге и вопросе. Смысл знака и правдивой пары известен. Поэтому неизвестны только частоты точного/частичного ответа/«не знаю». Следствие E004: истинная ценность равна e V_exact + b V_partial. Этот класс специально проверяет ограниченный механизм и не покрывает неидентифицируемые каналы E004.

## Данные и фиксированный исполнитель

Pinned VOI_communication commit `27466a7832d5aafff82017a659e08942e18b01ae`. Сохраняем E002 splits: 577 fit, 145 validation, 90 development holdout. Первые 72 validation-каталога служат отдельным пулом адаптации; остальные 73 не используются. Ни fit, ни adaptation каталоги не пересекаются с 90 каталогами проверки (хеш канонического каталога). Prior — 577 fit-профилей с исходной частотностью, не равномерное распределение по уникальным векторам.

Предложения, 8 вопросов и категориальные ответы те же. Один и тот же Bayes-executor выбирает действие по известному prior после знака/пары, после «не знаю» сохраняет исходный выбор. При данном классе каналов эти решения не зависят от неизвестных частот типов ответа. Не обучаем отдельного исполнителя для каждой policy.

Одна запись журнала: каталог, равновероятный выбор одного из 8 вопросов или no-ask (propensity=1/9), ответ, выбранное действие, **одна фактическая награда** этого действия. Пользователь сэмплируется из prior независимо для каждой записи. Скрытый профиль и награды остальных действий не передаются learner. No-ask остаётся кандидатом с известной нулевой ожидаемой выгодой: обучать его при известном prior не требуется.

## Режимы, бюджеты и обучение

10 независимых seed: 20261027…20261036. У всех методов в каждом seed одинаковые 4096 source-взаимодействий; в каждом target одинаковый вложенный журнал из 50/200 взаимодействий на adaptation-каталогах. Нулевой бюджет означает frozen transfer.

Source-канал: как E002, e=base[q]−.15 span, b=.2+.1 span. Контроль target=source. Второй target: умножить e на `[.35,1,.6,.9,.5,.5,.5,.5]` для price/stops/layover/arrival/4 airlines, b не менять, недостающую массу отправить в «не знаю». Это **искусственная заранее зафиксированная смена канала**, не эмпирическое описание людей; её не подбираем по результату. Предпочтения и каталоги не меняем.

Сравнения:

1. no-ask, random question, ideal-sign question, oracle с известными частотами (только evaluator).
2. Simple: частоты трёх типов по каждому вопросу, Dirichlet(1,1,1); ценность = частота exact × V_exact + частота partial × V_partial. Нет зависимости частоты от каталога.
3. Factorized: линейная модель вероятностей трёх типов по `[1, span]` отдельно для вопроса; ridge=1, проекция предсказаний на simplex. Затем та же аналитическая формула ценности.
4. Direct raw: регрессия на фактическую награду минус **ожидаемую** награду исходного действия при наблюдаемом ответе. Это control variate из известного prior; награда no-ask того же скрытого пользователя не раскрывается.
5. Direct denoised: тот же алгоритм и признаки, но target — условное ожидаемое улучшение решения после наблюдаемого ответа. Оно вычисляется из известного prior и смысла ответа, без знания текущего скрытого профиля. Это честный, но сильный аналитический контроль, а не будущий универсальный LLM-метод.

Прямые признаки отдельно по вопросу: `[V_exact, V_partial, span V_exact, span V_partial]`; они точно выражают истинную функцию в данном классе. Масштабирование только по всем fit-каталогам; ridge=1. Все методы имеют доступ к тем же наблюдениям, prior и аналитическим компонентам. Различия supervision и использования аналитики указываем явно. Direct predictions ограничиваются [0,V_exact] только потому, что в этом конкретном канале это корректно.

Для адаптации все модели имеют source-приор эквивалентной силы 32 source-взаимодействия (из 9 действий 8 являются вопросами), затем используют только 50/200 target-наблюдений. Для регрессии сохраняется source Gram, уменьшенный в 4096/32 раз, и центрирование на source weights; ridge=1 вокруг source weights. Для simple используются source-частоты с соответствующим pseudocount. Дополнительно pooled версии получают source+target без уменьшения веса source. Это проверяет условие H3 об обычном смешанном обучении. Бюджет не включает новые контрфактические ветвления.

## Оценка и критерий вывода

Затраты вопроса: 0, .02, .10 в исходных единицах линейной полезности (не рубли). Для всех кроме fixed no-ask/random выбираем максимальную положительную предсказанную чистую выгоду, иначе no-ask; равенство разрешается в no-ask. Основная метрика — точный ожидаемый regret + цена на 90 development-каталогах; дополнительно gap к oracle, частота вопросов, MSE ценности. Интегрированная **истинная ценность вопроса с неизвестным каналом**, усредняющая все возможные ответы, доступна только evaluator и не используется как обучающая метка. Условные ожидания по общему известному prior после уже наблюдаемого ответа и аналитические компоненты V_exact/V_partial доступны всем методам; это явно сохранённая привилегированная структура, а не полностью безмодельное обучение.

Отдельный журнал из 4096 взаимодействий на development-каталогах используется для IPS/DR оценки политики. Журнал не обучает модель и не выбирает гиперпараметры. IPS/DR сравниваем с точной оценкой как аудит наблюдаемой обратной связи; эти известные методы не называем вкладом. Выгоды/разности усредняем парно по seed; интервалы по 10 seed характеризуют только случайность сбора данных при фиксированных каталогах, не перенос на новые среды и не независимость всех строк.

Практический диагностический ориентир до запуска: улучшение mean loss ≥.005 native utility над **simple и direct denoised**, а также преимущество над pooled, заслуживает дальнейшей проверки; меньший/нестабильный эффект не является основанием для масштабирования модели. Даже прохождение этого порога не подтверждает публикационную новизну.

Проверки: доступ learner не содержит скрытый профиль/все награды; split-хеши; нормировка каналов; точное совпадение decomposition с явным перебором; no-ask и unknown имеют нулевую аналитическую выгоду; условные targets не используют скрытое состояние; одинаковые журналы методов; сохранение seed, хешей кода/данных/протокола, fitted weights и per-seed результатов. Никаких API, новых моделей или библиотек.
