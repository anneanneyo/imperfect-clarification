# E016: заранее разделённая проверка текстового selector

27 октября 2026. До отбора E016 и новых генераций. E014/E015 полностью известны. E015 ridge66.67% не превысил fixed issue68.75%, хотя обошёл нестабильный leave-one-out train-constant. Здесь проверяем те же фиксированные методы на большем отдельном split. Новая архитектура/новизна не заявляются.

## Eligibility и разделение

Тот же закреплённый Lavoir banking_support train, SHA2566641c847f59d539fc99de6dae24f92babeb0358c68699514528e23f3c8c71365. Только case-группы с kind=a; структурная предварительная проверка обнаружила485 таких групп, в каждой один исходный текст. Текст нормализовать casefold, collapse whitespace, trim. Совпадающие нормализованные начальные тексты объединить в компоненту. Полностью исключить компоненты, содержащие любую из24 development case E014, а не только отдельные профили.

Идентификатор компоненты — SHA256("E016-v1:" + newline-joined sorted case IDs). Отсортировать оставшиеся компоненты по этому хешу. Первые96 — train; следующие48 — test. Все профили kind=a каждой case-группы сохраняются. Не использовать gold/outcome/oracle для отбора. Компоненты и их роли заморозить до генераций. Официальные test_seen/test_zeroshot Lavoir не читать.

Веса: каждая компонента равновесна внутри split, case внутри компоненты равновесны, профили внутри case равновесны. Selector получает один нормализованный исходный текст на компоненту; исполнитель — точный первоначальный текст источника, как в E014. Это тест новых компонент внутри одного опубликованного train-workflow, не новый независимый домен.

## Executor и бюджет

Тот же model revision, E014 system с полными правилами, те же ответы/вопросы источника, greedy seed20261027, max64, input<=4096, strict JSON parser. Исполнитель не видит profile/gold/evidence/reveal/oracle. Ровно6 ветвей на профиль: no-question и5 probes. Точные prompts объединять; между train/test общих полных prompts быть не должно.

До запуска заморозить весь source subset, связь branch→prompt, selector inputs, rendered tokens и code/model/input hashes. Ограничение: до1200 уникальных train prompts и600 test prompts. Если превышено — остановить подготовку для пересмотра объёма до исходов; не фильтровать удобные ветви. Shards до600 prompts, до30 минут каждый, максимум3 shards/90 минут inference. При незавершённой shard сохранять partial outputs и missing, не перезапускать плохие ответы. Invalid=0; missing не ноль. При missing training labels не проводить обычный fit, а сначала зафиксировать неполноту. Основные метрики ранжирования только при полном replay.

## Последовательность с закрытыми test outcomes

1. Подготовить и заморозить inputs и split, проверить группировку и факты по schema/reveal машинно. Прежние семантические оговорки о синтетических текстах сохраняются; все новые тексты не объявлять вручную проверенными.
2. Запустить **только train** branches и получить training accuracy labels. Выбранные case не удалять по качеству текста или результата.
3. Обучить точный E015 TF–IDF+ridge(alpha1,max_features2000), train-only vocabulary/IDF, clipping. Targets — средняя observed accuracy каждой из6 ветвей внутри компоненты. Constant выбрать один раз по train utility. Cost0.05, tie-order прежний. Никакой настройки по test.
4. Сохранить/заморозить все test predictions и выбранные вопросы **до первого test inference**. Верификатор восстанавливает ridge через SVD и проверяет отсутствие test targets в fit. Сохранять хеш prediction-файла в каждом test generation manifest.
5. Только затем запустить test branches и оценить заранее сохранённые predictions. Не переобучать, не подбирать alpha/threshold, не выбирать удачную формулировку после оценки.

## Сравнения и метрики

Ridge, train-chosen constant, no-question, все5 фиксированных вопросов, uniform-random среди вопросов. Показать accuracy, utility, ask rate, forecast MAE, choices, paired utility differences ridge-minus-train_constant и ridge-minus-fixed_issue. All-test best fixed и oracle по видимым компонентам — только post-hoc ориентиры. Скрыто-профильный oracle не превращать в доступный competitor.

Для двух заранее названных paired differences: component bootstrap по48 test-компонентам,10000 resamples, seed20261027, percentile95% интервал. Это описательная оценка вариабельности по этому малому набору компонент, не сертификат общности и не correction множества просмотренных исследований. Не делать p-value claims. Отдельно показать per-component outcomes, чтобы интервал не скрывал единичные случаи. Ответы на каждый вопрос sampled один раз; интервалы не покрывают вариативность новых ответов для того же профиля или других моделей.

Test semantic audit после исходов, если потребуется, описательный: не менять primary scores и не исключать ошибки ради улучшения. Новые exclusions не добавлять в primary comparison. Схема reward/class точно проверяема, но соответствие LLM-generated текстов скрытым профилям не гарантировано только структурными проверками.

## Следующее решение

Если ridge не превосходит сильные фиксированные вопросы, не объявлять успех по сравнению со слабым constant. Зафиксировать размер и неопределённость различий; результаты использовать для следующего обоснованного дизайна, не для подбора выгодного test subset. Если преимущество есть, требуется отдельная более сильная/альтернативная executor проверка, сравнение factorized/direct при одинаковом feedback и независимая агентная среда. В любом исходе этот опыт не завершает публикационную цель.
