# E014-C: контроль без новой информации

27 октября 2026. **Post-hoc дизайн после результатов E014, до новых генераций.** В E014 вопрос об имени исправил конечный выбор в одной case-группе, хотя имя не входит в правила маршрутизации. Нужно проверить чувствительность исполнителя к изменению формы диалога, прежде чем обучать сложный selector на всём разрыве до oracle.

Сохранить все 24 исходные case-группы и 65 профилей E014. Не отбирать только ошибки. Для каждого первоначального сообщения создать две ветви с неизменным системным сообщением E014:

1. `repeat`: assistant «Could you repeat the information you already provided?»; user — точная копия первоначального сообщения.
2. `no_extra`: assistant «Is there anything else you can tell me?»; user «I don't have any additional information to provide.»

Это созданные нами отрицательные контроли, не опубликованные или человеческие ответы. В них нет новых фактов о скрытом профиле. Повторение гарантированно полное по конструкции; не утверждать, что реальные люди всегда повторяют информацию. В отличие от `unknown` исходного симулятора здесь даже вероятность данного ответа не связана с профилем.

Не менять модель, правила, parser, seed, decoding, token limits. Максимум48 уникальных prompts, одна генерация на точный prompt, без повторов. До запуска сохранить pack, branch links и manifest. Все три кода runner/E014/control и исходный E014 manifest входят в проверку хешей.

Метрики те же case/profile веса; точность каждого контроля, изменение относительно no-question E014, число случаев изменения метки и улучшения/ухудшения. Показать полный набор и ранее заданные21 case без семантических неоднозначностей. Для условного сравнения пользовательской нагрузки считать каждый контроль одним вопросом с ценой0.05, но не объявлять его проверенной практической стратегией. Runtime failures и invalid отдельно. Не выбирать лучший из двух контролей отдельно для каждого профиля под видом доступной политики.

Цель — диагностировать, насколько формальное улучшение final accuracy возможно без новой информации. Изменение ответа при неизменных фактах — не автоматически ошибка: при неопределённости допустимы разные классы. Поэтому отделить полностью определённые по schema случаи от неоднозначных, и связать улучшения с конкретными правилами. Сравнение ограничено малым исполнителем, искусственными контролями и development cases.
