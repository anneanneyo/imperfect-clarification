# E001a — контролируемая диагностика до LLM-запуска

Протокол записан до первого запуска кода E001a. Это локальная фиксация решений, не внешняя пререгистрация.

Цель: проверить, сколько ошибки при смене ответимости устраняет частотная оценка. Используем внешние каталоги рейсов, но синтетическую популяцию и формальные ответы. Это отдельный нижний по сложности уровень E001, не воспроизведение агента Dong.

- Данные: pinned commit из внешнего аудита. Каталоги — шестой раунд всех 89 подходящих eval-записей, без случайного повторного выбора. Распределение скрытых предпочтений — равномерное по 722 train-записям (повторы профилей сохраняют эмпирическую массу). Реальные eval-предпочтения НЕ используются. Все методы знают один и тот же эмпирический prior. Это сильное упрощение, не обучение belief.
- Пять фиксированных вопросов: знак предпочтения цены, числа пересадок, длительности пересадки, времени прибытия и четыре знака предпочтений авиакомпаний. Последний ответ раскрывает сразу четыре знака; стоимость условно одинакова. Ответы формальные, не свободный текст.
- Содержательный ответ точно сообщает соответствующую категорию; отказ независим от скрытой цели при фиксированном типе вопроса. При отказе belief неизменен. Исполнитель у всех один: точная максимизация ожидаемой награды по posterior.
- Режимы в указанном порядке вопросов: source=(.9,.9,.9,.9,.9); unchanged=source; selective=(.2,.9,.5,.8,.9); uniform_drop=(.3,.3,.3,.3,.3). Это придуманные режимы, не измеренное поведение людей.
- Source calibration: 500 наблюдений, по 100 на тип. Target adaptation: 0/50/200 наблюдений, сбалансированно по типам. Seed=0..29; seed определяет только бинарные ответы калибровки. Адаптатор получает тип вопроса и факт ответа, без hidden theta, режима, utility и незаданных ответов. Он адаптируется к популяции между задачами, не к одному человеку.
- Оценка вероятности: Beta(1,1) + наблюдения. При budget=0 используется source estimate; при 50/200 — target-only estimate. Отдельный baseline pooled объединяет source и target. На первом шаге не обучаем нейросеть или direct value head.
- Методы: no-ask; uniform random question; ideal-answer EVSI; information gain с source estimate; EVSI source; EVSI pooled; EVSI target-only; oracle-rate EVSI (знает истинные вероятности как отдельный reference). Дополнительно oracle-rate IG отделяет несовпадение целей IG/полезности от ошибки канала.
- Цена 0 и 0.02 в исходных единицах награды. При нулевой цене селекторы задают ровно один вопрос. При цене 0.02 EVSI может отказаться; IG выбирает вопрос по энтропии и спрашивает, если его предсказанная конечная выгода превышает цену. Random всегда спрашивает.
- Основная метрика: ожидаемый regret выбранного рейса + цена вопроса, меньше лучше. Все скрытые цели и исходы ответа суммируются точно; Monte Carlo-шума evaluator нет. Отдельно частота вопросов и разрыв относительно oracle-rate EVSI. При известном prior этот reference оптимален среди данного пула и no-ask, но не среди всех возможных вопросов/агентов.
- Отчёт: средние по 89 каталогам и 30 калибровочным seed; диапазон по seed; task-cluster bootstrap усреднённых по seed попарных различий с оговоркой об общей синтетической популяции. Seed не является новой независимой задачей.

Решение: если простая адаптация существенно приближается к reference, этого недостаточно для нейросетевой ставки. Если зазор остаётся, сначала проверяем статистическую неопределённость и цену адаптации. Независимость отказа от цели и известный prior делают задачу особенно удобной для частотного метода; результат нельзя переносить на смысловые ошибки и реальные диалоги.

## Дополнение после первого результата, до запуска абляции

Первый запуск показал доминирование bundled-вопроса об авиакомпаниях (85 из 89 каталогов у oracle при selective). Поэтому добавлена **разведочная абляция**, не независимое подтверждение: восемь вопросов, каждый раскрывает знак одного коэффициента. Порядок price/stops/layover/arrival/american/delta/jetblue/southwest. Selective=(.2,.9,.5,.8,.9,.9,.9,.9); остальные вероятности unchanged=.9 и uniform_drop=.3. Бюджеты и evaluator прежние. Калибровочные вопросы чередуются по восьми типам, число наблюдений отличается максимум на один. Pooled объединяет подсчёты по типу, а не склеивает последовательности со смещением индексов. Первоначальные результаты сохраняются; абляция нужна для проверки зависимости вывода от неравной детализации вопросов.
