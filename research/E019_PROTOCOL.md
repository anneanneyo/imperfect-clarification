# E019: понимание фактов отдельно от применения правил

27 октября 2026. Протокол закрепляется до новых генераций. Диагностический опыт после E018; не независимый тест question selector и не предложение нового метода.

## Вопрос и входные данные

Может ли та же локальная Qwen3-4B-Instruct-2507-4bit извлечь явно сообщённые банковские факты достаточно надёжно, если от неё не требуется одновременно выбирать отдел? Выбор отдела по извлечённым фактам затем выполняется проверяемой программой.

Использовать все 24 E014 development-case и все 96 E016 training-компонент, только исходные сообщения без вопросов. Внутри case исходный текст и evidence одинаковы во всех профилях: одна генерация и одна единица оценки на case. Всего 120 уникальных входов. E016 test не включать. Не отбирать только семь известных ошибок, не редактировать спорные тексты, не исключать неудачные ответы.

Извлекаемые поля: issue (пять категорий), product (четыре), money_gone и compensation (yes/no). Модель получает только исходный текст и фиксированную инструкцию о категориях и формате. Ни evidence, ни profile, ни gold, ни posterior, ни старый ответ исполнителя не входят в messages. Исходные аннотации используются для оценки, а не подачи модели.

Каждое поле — непустой список допустимых значений. Неизвестное поле представляется полным доменом. Частичный ответ — множество указанных альтернатив; отрицание yes означает no, но отсутствие yes не означает no. Для исходных 120 сообщений аннотации содержат только singleton/unknown: **partial-ответы и их обновление этим опытом ещё не проверяются**.

## Исполнение правил

Перечислить все 80 сочетаний четырёх полей. Применить шесть исходных правил в прежнем порядке. Для частично известных фактов вернуть множество отделов, достижимых на совместимых сочетаниях. Не выбирать правильный отдел с помощью скрытого gold и не превращать множество отделов в окончательный ответ по неуказанному prior.

Это намеренно отличается от исходного генеративного prior, который имеет только 44 положительных сочетания. До генераций независимая общая реализация schema-правил совпала с прямым интерпретатором на всех 80 сочетаниях и 4185 непустых декартовых множествах фактов; проверен строгий parser на 31 неверном формате. [Аудит контракта](../results/e019_contract_audit/summary.json).

У пяти из 120 случаев множество допустимых отделов шире, чем support исходного posterior, из-за структурных нулей prior. В training единственный отдел по фактам получается в **38**, а не 39 случаях; в development — в 12. Основной знаменатель однозначных случаев E019 — 38/12. Эти данные определены до генераций, не по исходам модели. Все случаи сохраняются в общей оценке.

## Заморозка и бюджет

Один prompt, реализованный в `experiments/structured_facts_e019.py`, без дальнейшего подбора. Та же pinned revision и веса, local-only loading, greedy temperature 0, seed 20261027. Изменяется задача и размер ответа: максимум **192** выходных токена, общий бюджет **1800 секунд**, максимум 120 генераций. Никаких повторов плохого вывода. При нехватке бюджета или пропуске генераций не вычислять обычный полный результат.

До запуска закрепить хеши протокола, скрипта, аудита математического контракта, source-файлов, model/tokenizer, cases, messages и rendered tokens. Сохранить начало каждой генерации и исходный output. Изменение prompt/весов/лимита после просмотра исходов требует нового эксперимента.

Допускается только один JSON object с ровно четырьмя ключами и непустыми списками допустимых неповторяющихся строк. Порядок списков несущественен. Fences, объяснения, лишние/дублирующиеся ключи, null, пустые списки и неизвестные значения — invalid. Runtime errors также invalid. Неверный output даёт нулевое совпадение по всем четырём полям; не удаляется из знаменателя. Лимитированный, но корректный JSON считается по содержанию, а finish_reason отдельно сообщается.

## Метрики

Отдельно для development и train:

- Точное совпадение всех четырёх множеств и среднее точное совпадение полей.
- По каждому полю: точное совпадение, исключённое допустимое значение (source set минус predicted set), потерянное ограничение (predicted set минус source set), invalid. Неверный singleton может давать оба вида расхождения.
- Точное совпадение множества отделов по предсказанным и аннотированным фактам.
- Среди 38/12 reference-singleton случаев: правильный однозначный отдел, неверный однозначный отдел, оставшаяся неоднозначность, invalid. Неоднозначность не засчитывается как успех из-за присутствия gold в списке.
- Число генераций, токены, время, память, runtime/format/length ошибки.

Это согласованность с синтетическими source-аннотациями. Не каждое расхождение доказывает ошибку модели: текст может не выражать аннотацию однозначно. Последующий смысловой разбор маркируется отдельно, не меняет primary score. Не называть slot accuracy качеством конечных действий или пользой вопросов.

## Заранее заданное решение

Переход к разработке полного question replay с этим структурированным исполнителем допускается только при одновременном выполнении на **всех 96 train-компонентах**:

1. Ноль invalid outputs.
2. Среднее точное совпадение четырёх полей не ниже 90% (не меньше 346 из 384).
3. Правильный однозначный маршрут не ниже 90% среди 38 reference-singleton случаев (не меньше 35 из 38).

Это прагматический development gate, не тест значимости и не заявление о переносе. Даже успешный gate требует отдельной проверки partial/unknown в ответах на вопросы и честного правила действия при оставшейся неопределённости. Не выбирать лучшие пороги после результатов.

Если gate не пройден, сохранить отрицательный результат, локализовать расхождения и выбрать следующий обоснованный контроль. Не запускать полный question replay и не подбирать prompt до прохождения. E016/E017 scores и старые outputs остаются неизменными.
