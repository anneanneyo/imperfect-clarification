# E018: проверка влияния названий отделов на исполнение правил

27 октября2026. После завершения и просмотра E016/E017. Диагностический control, не независимая проверка обученного selector. Исходное наблюдение: в7 семантически ясных training cases исполнитель нарушил явно заданные правила, иногда игнорируя отрицание компенсации или принимая failed_payment за fraud.

Проверяем, уменьшатся ли ошибки, если оставить все правила, но заменить названия выходных отделов нейтральными кодами. Это меняет семантику и токенизацию label одновременно; нельзя из одного опыта установить отдельный причинный эффект каждого компонента. Это не новая архитектура и не попытка подобрать выгодную формулировку по test.

## Фиксированный контроль

Использовать все96 train-компонент E016 и все24 development case E014. **E016 test не использовать.** По одному no-question prompt на видимый исходный текст; все соответствующие source profiles сохраняются. Два набора оценивать отдельно, весаcase/componentuniform иprofileuniforminside прежние. Не ограничиваться9 известными ошибками.

В исходном E014 system заменить точные слова label:cards→U1,fraud→U2,loans→U3,accounts→U4,complaints→U5. Другой текст, порядок правил, пользовательское сообщение и пример JSON остаются с тем же содержанием; пример получаетU1. Никаких новых фактов, правил, вероятностей или демонстраций правильных решений. Та же модель/revision,greedy,max64. Новый sole-key JSON `team` должен содержать один изU1…U5; затем независимо декодируется обратно. Invalid=0;missing блокирует обычное полное сравнение. Не менять parser или prompt после исходов.

До генераций закрепить protocol/code,source-links,заменённый system,rendered tokens имодельные хеши. До120 уникальных prompts,однаshard,30 минут максимум. Без повторов плохих outputs. Любое превышение останавливает preparation, а не фильтрует случаи.

## Анализ и правило решения

В каждом издвух наборов сравнить старый и новый no-question accuracy,invalid outputs,парные улучшения/ухудшения. Отдельно показать случаи с вырожденным исходным symbolic route posterior, а также7 ясных ошибок train:00037,00384,00210,00390,00406,00176,00348. Спорные00155 и00484 остаются вобщей оценке; не входят вgate чистых ошибок.

Нейтральный prompt можно считать кандидатом для дальнейшей проверки, только если исправленыкак минимум4 из7 ясных случаев **и** общая96-train accuracy не снизилась. Этот gate не означает готовность новой модели или подтверждённое превосходство. Еслиусловия невыполнены, не перебирать перестановкиU1…U5доуспеха; сохранить отрицательный control и перейти к отдельно выбранному более надёжному executor. В любом исходе вопросные политики нуждаются в новой проверке, поскольку контроль измеряет только no-question, аE016 test уже известен.
