# E021: сохранение фактов после partial/unknown ответа

8 ноября 2026. Условный следующий контроль, записан во время E020 до просмотра его агрегированных исходов. **Запуск разрешён только если primary gated E020 проходит свой заранее заданный gate и независимую проверку.** Если gate не пройден, E021 остаётся подготовленным, без модельных результатов.

Использовать все 70 partial и 62 unknown опубликованных probes из 274 E016 training-профилей. Они дают 125 уникальных диалогов (67 partial, 58 unknown) из 64 исходных case. Выбор не зависит от успехов E020, остальные виды ответов в этот опыт не входят. Это целевой диагностический набор, а не репрезентативная оценка частот и не независимый новый test. Никаких исключений по исходам.

Вход: прежнее исходное пользовательское сообщение, опубликованный вопрос в assistant-role, опубликованный ответ в user-role. Hidden profile, source kind, reveal, evidence и ожидаемые значения исключены из messages. Система извлекает итоговые четыре множества фактов. К E020-инструкции добавляется один фиксированный абзац: учитывать всю историю, сохранять ранее сообщённые факты, вопросы ассистента не считать свидетельством и не считать «не знаю» отменой известного факта. Это отдельная заранее указанная адаптация инструкции, не утверждение о неизменном prompt.

Эталон: пересечение initial evidence с reveal каждого поля; missing=полный домен. Все пересечения непусты. У одинакового полного диалога эталон должен совпасть; конфликт блокирует подготовку. Unknown эталон равен initial; частичный ответ может сократить множество отделов. Цитата проходит механический gate, только если является точной подстрокой одного из **пользовательских** сообщений, а не вопроса. Parser и fallback как в E020.

Основные метрики отдельно для 67 partial и 58 unknown уникальных диалогов: exact каждого поля, известных/неизвестных полей, всех четырёх полей, множества отделов; correct/wrong/uncertain для reference-singleton. Одинаковые prompts исполнить один раз, связи со всеми 132 исходными probes сохранить. Такие dialogue-level проценты не выдавать за case-uniform policy success.

Для unknown дополнительно сравнить gated факты с исходным E020 для того же case: число изменённых полей, вновь потерянных допустимых значений и восстановленных значений. Изменение при ответе IDK может исправить старую ошибку; отдельно сверять с source facts, не объявлять любое изменение вредом. Сохранять raw/gated и исходные цитаты.

Gate надёжности для будущего общего replay: в каждой из двух групп zero invalid, >=90% exact fields и >=95% known fields. Считается на полной группе без исключений. Это development decision, а не статистическое доказательство. При неуспехе не доучивать вопросную политику на ненадёжных извлечённых значениях и не подбирать prompt по этим исходам.

Та же pinned модель, greedy, seed20261108, max384 tokens. Максимум125 генераций,1800 секунд, без повторов. Закрепить protocol/code/input/runtime/model hashes до запуска. Все outputs/errors/length statuses сохранять; incomplete блокирует полный score. Не делать заявлений о пользе обученной политики, новом response-channel model или переносе на людей по этому опыту.
