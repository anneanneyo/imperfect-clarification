## E015: первый доступный текстовый baseline

Следующий шаг — **выполнить обучение простого оценивателя**, а не ещё один общий аудит. Отдельный E015 protocol зафиксировать до fitting, честно отметив, что результаты E014 уже просмотрены. Никакого заявления о слепом финальном тесте:24case — development материал.

Единица — исходная case-группа с одинаковым доступным сообщением; все её profile и reply variants остаются вместе. Проверить также точные одинаковые видимые входы между case-группами, объединять такие группы при cross-validation. Input selector: только исходный видимый текст и фиксированный список вопросов. Не подавать gold, ID, profile, posterior, reveal, source oracle, ответ на ещё не заданный вопрос или модельные исходы текущей test-группы.

Labels для offline training: в каждой case-группе средняя 0/1 точность фиксированного E014 исполнителя для каждой из 6 ветвей (no-question+5 вопросов), по тем же равным profile весам. Один sampled response не превращать в точный EVSI; это noisy empirical utility target. Все контрфактические training labels получены из ветвления, их число учитывать и не называть обучением только по одному feedback на диалог.

Первый метод: стандартная TF–IDF word unigram/bigram + multi-output ridge с intercept, фиксированным alpha1 и train-only vocabulary/IDF. Сначала проверить наличие numpy/sklearn в уже доступных окружениях; не менять пользовательские зависимости ради baseline. Допустима независимая реализация dual ridge через numpy. До запуска зафиксировать tokenization, max_features2000, normalization, clip predicted accuracy в[0,1], цену.05 и tie-order. Гиперпараметры по этим 24case не подбирать.

Сравнения: no-question; фиксированные вопросы; постоянная ветвь, выбираемая только по training groups; uniform-random question; ridge-selector. Leave-one-group-out, все результаты хранить по fold. Предсказание на held-out group вычисляется до чтения её labels для scoring. Post-hoc oracle оставить отдельно как диагностический ориентир, не конкурент с тем же информационным доступом.

Проверить предсказания независимыми формулами, group separation, train-only preprocessing и выполнение правила одного выбора для одинакового видимого входа. Показать weighted accuracy, utility, ask rate, per-question выборы, MAE прогнозов; полный набор и заранее объявленную чувствительность 21case. Чувствительность не использовать для настройки или выбора победителя. Не считать 24fold независимыми экспериментами и не выдавать p-values за подтверждение нового метода.

## Решение после fitting

Если простой текстовый метод не превосходит training-chosen constant, это не доказательство невозможности задачи: мала выборка и простые текстовые признаки. Зато станет понятно, что наблюдаемый oracle gap ещё не превращается автоматически в доступный результат. Следующий объём данных и новый test split определить заранее до расширения локальных прогонов; не выбирать новые cases по текущим ошибкам.

Если baseline показывает содержательный перенос, нужно проверить более сильного/альтернативного исполнителя и расширение внешних case-групп. Улучшения должны пережить простой baseline, одинаковый feedback budget, реальный test и влияние ошибок исполнителя. Только после этих проверок переходить к сравнению direct/factorized learned estimators и адаптации, сохраняя исходную тему.
