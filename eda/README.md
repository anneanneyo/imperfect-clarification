# EDA

Анализ 12 задач UserBench: состав данных, пропуски, ошибки разметки, распределения, сравнение исполнителей и две проверки аугментаций.

- [Notebook с результатами](../EDA.ipynb).
- [Практическая ценность, PDF](../output/pdf/practical_value.pdf).
- [Апдейт руководителю](../updates/2026-11-08.md).

## Запуск

Из корня репозитория в отдельном Python-окружении:

```bash
python -m pip install -r eda/requirements.txt
python eda/build_eda.py
```

Скрипт использует сохранённые данные и ответы модели, выполняет ячейки и записывает графики в notebook. Затем собирает PDF. Повторно запускать модель или скачивать данные не требуется.

Материалы подготовлены 8 ноября по [требованиям второго чекпойнта](https://docs.google.com/document/d/1Izow1n6RTf-iP6MEXE3zVH9i5-gBoFUr4uJvCLKhh1U/edit), срок которого — 7 ноября, 23:59.

Предыдущий анализ другой синтетической задачи находится в [архиве](../outputs/checkpoint2_2026-10-27/REPORT.md).

В задании для DL-трека также рекомендуется интерпретация признаков через модель.
В текущем EDA показано сравнение качества при раскрытии предпочтений, но нет
отдельного разбора внутренних представлений Qwen. Это необязательный пункт,
который пока выполнен частично.

Текущий набор подходит для первичного анализа и отладки. Для оценки метода
выбора вопросов ещё нужны новые задачи, проверка правил оценки и независимый
пересчёт всех ранжирований E027. Количество вариантов в таблице не увеличивает
число независимых задач: их здесь 12.
