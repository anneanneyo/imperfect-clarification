# Уточняющие вопросы при неполных ответах

Исследуем, как выбирать уточняющий вопрос по его влиянию на конечное решение. Пользователь может раскрыть только часть предпочтений или ответить «не знаю». Основная гипотеза — раздельная модель цели пользователя и возможного ответа лучше переносится на новые условия общения, чем прямое предсказание пользы вопроса. Планируем сравнение при одинаковом числе уточнений.

## Данные

Используем 12 задач из обучающей части UserBench. В каждой нужно выбрать перелёт, жильё, машину и ресторан: по 18 вариантов и два скрытых предпочтения для каждой части поездки. Всего 48 отдельных выборов и 864 варианта.

Это синтетические задачи. Выборка уже использовалась при разработке; качество на новых задачах по ней не оцениваем. Происхождение данных и лицензия — в [THIRD_PARTY.md](THIRD_PARTY.md).

## Первые результаты

Проверили Qwen3-4B без дообучения, простую эвристику по совпадению слов и цене, случайный выбор.

Доля выбранных вариантов, допустимых по разметке UserBench:

| Метод | Без уточнений | Раскрыты оба предпочтения |
|---|---:|---:|
| Случайный выбор | 16,67% | 16,67% |
| Эвристика | 19,44% | 45,83% |
| Qwen3-4B | 20,83% (10/48) | 64,58% (31/48) |

В правом столбце предпочтения раскрыты для всех четырёх частей поездки. Таблица показывает, как дополнительная информация влияет на выбор исполнителя. Для сравнения способов выбора одного вопроса нужен отдельный расчёт.

У Qwen пока не нашли строгой смены лучшего вопроса при переходе от полного ответа к частичному по нашим правилам проверки предпочтений. Такой эффект был у простого символического исполнителя, но на языковой модели он не подтвердился.

В исходной разметке есть спорные ответы, а в задачах повторяются шаблоны. Поэтому дополнительно проверяем выполнение конкретных предпочтений; если сведений недостаточно, оставляем результат неизвестным. Эти правила ещё требуют независимой проверки. Для UserBench оценщик пользы вопроса пока не обучен. Раннее сравнение простых прямого и раздельного оценщиков в математической среде описано в [E005](research/E005_RESULTS.md).

## Запуск EDA

Из корня репозитория в отдельном Python-окружении:

```bash
python -m pip install -r eda/requirements.txt
python eda/build_eda.py
```

Команда собирает notebook с графиками и PDF о применении проекта. Используются сохранённые данные и ответы модели. Скачивание весов и повторный запуск Qwen не нужны.

Проверки экспериментов и требования к окружению описаны в [REPRODUCE.md](REPRODUCE.md).
