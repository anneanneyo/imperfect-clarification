# Проверка сохранённых результатов

Рабочая ветка: `codex/research-e023`. Python 3.10+ достаточен для проверок E023/E024; новых модельных генераций они не требуют. Старые эксперименты имеют собственные зависимости и исторические абсолютные пути. Их протоколы, скрипты и исходные результаты сохранены без переписывания.

## E023

```bash
python3 experiments/reproduce_e023.py
```

Команда проверяет хеши, находит или скачивает только закреплённый banking train Lavoir и выполняет независимый проверяющий код E023. Официальные test-файлы не нужны. Для переноса на другой компьютер заменяются только два обращения к историческому пути исходного train-файла в исполняемом AST; файл проверяющего кода и замороженные манифесты не меняются. Выборка, правила, веса, подсчёты и аудит пересчитываются полностью.

## E024

Сохранённые результаты: `results/userbench_contract_e024/`. Их входы и код закреплены в `manifest.json`. Скрипт по умолчанию не перезаписывает готовый результат. Для повторения скопируйте `experiments/userbench_contract_e024.py` и `research/E024_PROTOCOL.md` в пустую временную структуру с теми же каталогами и запустите оттуда. Он скачает три файла UserBench по закреплённому commit, проверит Git blob SHA и выполнит 12 ручных траекторий и инъекцию отказа генератора. Модельные/API вызовы и benchmark-данные не используются.

## E025

Аудит официального train UserBench: Python, `pyarrow==21.0.0` из `experiments/requirements-e025.txt`. Зависимость устанавливается в отдельное окружение. Из корня репозитория:

```bash
python -m pip install -r experiments/requirements-e025.txt
python experiments/audit_userbench_train_e025.py --verify --download
python experiments/verify_userbench_e025.py
python -m unittest discover -s experiments -p test_userbench_choice_adapter.py -v
```

Первая проверка воспроизводит и побайтно сравнивает артефакты; `--download` загружает только два закреплённых файла, если их нет в cache. Второй скрипт независимо проверяет отбор, все видимые варианты, метки и ключевые находки непосредственно по исходным данным. Третий запускает 9 поведенческих тестов адаптера. Модельные вызовы не требуются. Cache по умолчанию — `~/.cache/clarification-research/userbench-80506d2`; можно задать `--cache PATH` обоим скриптам.

Важно: общий JSON авторов содержит разные splits. Скрипты извлекают только заранее выбранные 12 train-ID; test parquet не загружается. `public_cases.json` — видимый вход нашего диагностического режима с готовыми меню. `private_cases.json`, `restaurant_evidence.json` и инвентарь предпочтений содержат скрытые эталоны и **не должны подаваться агенту**. Это модификация для проверки данных, не воспроизведение исходного агентного benchmark.

## E026

Основной расчёт использует стандартную библиотеку Python 3.9+ и сохранённые E025-данные. Ничего скачивать, запускать модель или устанавливать pyarrow для E026 не нужно.

    python3 experiments/run_semantics_e026.py --verify
    python3 experiments/verify_semantics_e026.py
    python3 experiments/review_semantics_e026.py
    python3 -m unittest discover -s experiments -p test_semantics_e026.py -v

Первая команда побайтно сверяет первичный прогон. Вторая независимо пересчитывает все границы и смены вопросов точными дробями, условно на сохранённой таблице T/F/U. Третья отдельно воспроизводит поправку Zillow Rental/Rentals и сверяет её результаты. Ни одна не переписывает первичные результаты. Четвёртая запускает 12 тестов.

Каталог criteria.json закреплён до расчёта исходов. Скрипт build_criteria_e026.py документирует построение и отказывается перезаписывать существующий каталог. Единственная поправка после просмотра исходов находится в review_*-файлах; использовать её нужно с явным указанием этого статуса. Независимая арифметическая проверка не заменяет независимую семантическую разметку.

Необязательное повторение графика: plot_semantics_e026.py, matplotlib 3.9.4. SVG и его манифест сохранены в результатах. Для основной проверки графическая библиотека не требуется.

## Архивные таблицы

Две большие построчные CSV ранних синтетических опытов хранятся в Git в gzip-формате. Чтобы восстановить исходные байты по старым путям:

```bash
python3 experiments/restore_large_results.py
```

Хеши проверяются до записи. Остальные файлы результатов доступны непосредственно. Исторические ссылки на личные временные каталоги в замороженных отчётах могут не работать на другом компьютере; это не команды установки и не подтверждение наличия этих каталогов.

Происхождение внешних данных: [THIRD_PARTY.md](THIRD_PARTY.md). Веса больших языковых моделей, окружения, ключи доступа, личные учебные работы и резюме в набор проекта не входят. Небольшие обученные матрицы оценщиков сохранены в `results/`.
