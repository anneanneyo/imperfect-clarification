# Апдейт по проекту — 8 ноября

Подготовила EDA по требованиям второго чекпойнта: данные, пропуски, качество разметки, распределения признаков, простые методы и проверка аугментаций. Основной файл — [EDA.ipynb](../EDA.ipynb), практическая применимость — [отдельный PDF](../output/pdf/practical_value.pdf).

Сейчас работаю с небольшим обучающим срезом UserBench: 12 задач, 48 отдельных решений и 864 варианта. Это синтетические задачи выбора перелёта, жилья, машины и ресторана. Тестовую часть пока не использовала.

При проверке нашлись неоднозначные эталоны: например, пользователь указывает конкретный город пересадки, а лучший вариант в разметке проходит через другой город. Поэтому отдельно считаю совпадение с исходными метками и выполнение проверяемых условий. Если данных для проверки нет, оставляю результат неопределённым.

Запустила локальную Qwen3-4B на 192 входах, без дообучения. По исходной метке допустимого варианта получилось 10/48 без дополнительных сведений и 31/48 при раскрытии обоих предпочтений для каждого аспекта. Это проверка исполнителя с полной информацией по всем четырём частям поездки, а не результат системы с одним уточняющим вопросом. Прямой пересчёт этих чисел включён в notebook.

Пока не удалось подтвердить на языковой модели прежний результат символического эксперимента — строгую смену лучшего вопроса при неполном ответе. Есть отдельное несовпадение по исходным меткам, но его недостаточно для общего вывода. Следующий шаг — разобрать ошибки исполнителя и проверить выбор вопроса на большем наборе с контролем повторяющихся шаблонов.
